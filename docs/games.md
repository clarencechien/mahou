## 全平台共通

| 項目 | 做法 |
|---|---|
| 判定基準 | **client 時間戳**（`performance.now() + offset`）。DO 只排序、去重、廣播，不看封包到達時間 |
| 對時 | 加入時 10 次 ping/pong 取最小 RTT 樣本；之後每 10 秒背景重對，漂移實測 <9ms/100s |
| 手機角色 | **純控制器**。畫面在電視上，手機不畫遊戲場景（省電、不發燙、眼睛留在大螢幕） |
| 大螢幕 | 384×216 內部緩衝，整數倍放大；文字一律用 DOM 疊層，canvas 只畫像素場景 |
| 感應器 | 進遊戲前在說明畫面就先要權限＋校準。iOS 的 `requestPermission()` 必須由 `click` 觸發，被拒會黏住 |
| 結束 | 管理分頁的「結束房間」會先自動匯出 JSON 再踢掉所有連線，讓 DO 休眠（計費防呆） |

### 開場說明流程（兩款遊戲共用）

1. 主持人按頂列的「開始 ⟨遊戲⟩」→ **不會直接開打**，先跳出說明卡
2. 說明卡上：規則三行、控制圖示、語音解說（`speechSynthesis`，中文女聲優先）
3. 同時所有手機切到**準備畫面**：要權限 → 校準 → 可以先試玩（點擊／搖動／傾斜都有即時回饋）
4. 說明卡顯示「N 人已就緒 / M 人已連線」，主持人看大家都好了再按「開始遊戲」

## 遊戲一：一二三木頭人（混合指令）

**人數** 1–8　**時長** 10 回合約 3 分鐘　**stage** `freeze`

### 規則

綠燈時大螢幕出一道指令，做對得 1 分。鬼轉身（紅燈）後還在動就倒扣 1 分。
判定完全看 client 時間戳，所以網路快慢不影響公平性。

### 五種指令（洗牌袋輪流出，不會連續重複）

| 指令 | 手機上 | 判定 |
|---|---|---|
| `math` | 個位數加減，四個答案選一個 | 選對＝得分。答案固定 0–9，誘答在 ±3 內 |
| `color` | 四色格選一個 | 選對＝得分。色差刻意拉大（ΔE<40 玩家分不出，見實測） |
| `tapN` | 「點 N 下」計數器 | 剛好 N 下＝得分；**超過就倒扣**，所以要停得住 |
| `shake` | 搖動計數 | 達標＝得分 |
| `dash` | 連續搖動提示 | 達標＝得分 |

### 紅燈判定

鬼轉身後給 **250ms** 的煞車寬限（`FREEZE_GRACE_MS`）。超過還在動 → 違規一次、倒扣 1 分，同一回合只扣一次。

### 說明卡文案

> **一二三木頭人**
> 綠燈時看大螢幕的指令，用手機做對就得分。
> 鬼一轉身就要停手，還在動會被扣分。
> 指令有加減法、選顏色、點幾下、搖手機——看清楚再動。

語音：`綠燈的時候，看大螢幕的指令，用手機做對就得分。鬼一轉身就要停手，還在動會被扣分。`

## 遊戲二：滑雪下坡

**人數** 1–8　**時長** 30 秒比距離　**stage** `ski`

### 規則

30 秒內滑最遠的人贏。手機直握、螢幕朝上平放。

| 動作 | 操作 | 效果 |
|---|---|---|
| 加速 | **連點畫面** | 點越快越快，但只推得到 11 m/s |
| 轉向 | **左右傾斜手機** | 閃樹和石頭；空中轉向力只剩一半 |
| 跳躍 | **把手機往上抬** | 踩到跳台才有用（見下） |

### 跳台是唯一的加速來源

連點有上限，要更快只能吃跳台：踩中一次 **+7 m/s** 的 surge，可以疊到 **24 m/s** 硬上限。
surge 按比例緩降（半衰期約 1.4 秒），所以要一路串跳台才維持得住高速。

**容忍值**（派對場合寧可寬鬆）：

- 起跳後 **0.9 秒**內壓到跳台都算數（`ARM_S`）——不是起跳當下判定，因為人的反應有快有慢
- 跳台判定範圍左右 ±70、前後 ±70 世界單位
- 手機提前 **0.55 秒**跳出「抬起手機！」並指示跳台在左邊還是右邊
- 沒踩到＝空跳，只是白跳一次（滯空 0.5 秒轉不太動），不倒扣

### 撞到障礙物

速度 ×0.45、暈 0.5 秒（暈的時候加速衰減 ×5）。跳躍中可以越過樹，石頭要跳更高。

### 調校常數（`public/client.html` 的 `SKI`）

| 常數 | 值 | 意義 |
|---|---|---|
| `TAP_ACC` | 2.4 | 每點一下加多少 boost |
| `DECAY` | 1.0 | boost 按比例緩降。**平衡點 ≈ 每秒點擊數 × 2.4**，停手約 0.7 秒掉一半 |
| `TAP_CAP` | 11 | 連點推得到的上限 |
| `DRIFT` | 4.0 | 不做任何事也會往下滑的底速——畫面永遠在動 |
| `RAMP_SURGE` | 7.0 | 踩中跳台的加速 |
| `SURGE_DECAY` | 0.5 | surge 的比例衰減 |
| `HARD_CAP` | 24 | 速度硬上限 |
| `LIFT_TH` | 6.0 | 抬手機的 z 軸加速度門檻（m/s²），基準線走低通所以斜著拿也有效 |
| `COURSE.SPEED_MUL` | 1.8 | 見下方「速度感調校」。`WORLD_PER_M = 22 × 倍率` |
| `STEER` | 260 | 傾到底的橫向速度（世界單位/秒） |
| `TILT_EMA` | 0.16 | gamma 的低通係數。連點會讓 gamma 抖，這是穩定度換反應速度 |
| `TILT_DEAD` | 3.5° | 傾斜死區 |

賽道常數在 `public/engine/course.js`：`BASE_WPM = 22`、`HALF_W = 260`、跳台佔物件數約 26%、平均每 1.4 秒來一組。

### 速度感調校（主控頂列的「⚙︎ 手感」）

速度還沒定案，所以三個旋鈕做成現場可調，數字記在主控這台電腦的 localStorage：

| 旋鈕 | 預設 | 影響 |
|---|---|---|
| **速度倍率** | 1.8× | 前進速度與障礙物間距**一起**放大。每秒遇到的障礙物數量不變（維持 1.4 秒一組），但每個物件掃過畫面的時間變短 → 變快而不是變難。下一場生效（倍率跟種子一樣由 DO 發，兩端才長出同一條賽道） |
| **地面密度** | 1.6× | 只縮放 Mode 7 的紋理取樣座標。雪地花紋變細＝每秒掃過的格子變多，難度完全不變的純視覺速度感。立刻生效 |
| **廣角** | 1.0× | 縮放 `f`。越廣角兩側掃得越兇，太廣會像魚眼。立刻生效 |

另外賽道兩側有一排標竿（`C.props`），**間距固定 165 世界單位、不隨速度倍率放大**——所以速度越快掠過越兇。速度感其實來自「每秒有多少東西刷過去」，不是玩家自己跑多快；這是 SFC 賽車遊戲的老招，順便把賽道邊界標出來。

定案之後把 `TUNE_DEF`（`public/host.html`）的預設值改掉即可。面板上的「複製設定」會把當下三個數字複製成一行字。

### 分割畫面

1 人全螢幕 → 2 人直切兩欄 → 3-4 人 2×2 → 5-8 人 4×2，沒人的格子純黑。
加入時分割線用 0.45 秒插值長出來，不會瞬間跳格。
**實測：捲動雪地 Mode 7 在 1/2/4/8 格都是 4.3-4.4ms** —— 分割數不是成本，總像素才是。

### 機器人實測（30 秒，4 個 headless client）

| 玩法 | 距離 | 跳台 |
|---|---|---|
| 快速連點、不理跳台 | 386m | 0 |
| 中速連點、追跳台 | 454m | 6 |
| 慢慢點 | 267m | 0 |
| 快速連點、追跳台 | 463m | 6 |

追跳台約多 20%，但不追也玩得下去——這是刻意的：長輩只連點也不會墊底太多。

### 說明卡文案

> **滑雪下坡**
> 手機平放拿好，30 秒看誰滑最遠。
> **連點畫面**就會加速，**左右傾斜**閃開樹和石頭。
> 看到藍色跳台，**把手機往上抬**就會跳起來——跳中了會衝很快。

語音：`手機平放拿好。連點畫面加速，左右傾斜閃開樹木。看到藍色跳台就把手機往上抬，跳中了會衝很快。三十秒，看誰滑最遠。`

## 已知風險（真機還沒驗）

| 風險 | 目前的緩解 |
|---|---|
| 連點時 gamma 抖動污染轉向 | EMA α=0.16 重低通 ＋ 3.5° 死區。代價是轉向變鈍 |
| 連點的震動誤觸發跳躍 | z 軸門檻拉到 6.0 m/s²、320ms 不應期。說明畫面可以先試 |
| iOS 拒絕感應器權限 | 退回螢幕上的跳躍按鈕，仍然玩得下去（只是沒有傾斜轉向） |
| 電視上的 4×2 分割看不清楚 | 角色高度約佔格高 27%；速度線與撞擊紅閃提供格子層級的回饋 |
| 主控音量 | master gain 0.28，接電視要現場調 |

## 0. 設計約束（全部來自實測，不是假設)

| 約束 | 數字 | 出處 |
|---|---|---|
| RTT 地板 | **~150ms**（wifi+wnam 與 5G 皆然） | Phase 0 網路量測 |
| 掉包率 | 0%（狂點 100 次/3 秒） | Stage 0 |
| 8 人同場 | DO p95 僅 +9ms | 假 client 壓測 |
| 對時漂移 | <9ms/100s；網路切換跳 ±27ms 後 10s 內回穩 | Phase 0 |
| 渲染 | WebGL 12 分割 1.0ms/幀（Chromebook 實機） | /bench |
| 跨螢幕色差 | ΔE<40 玩家分不出 | 顏色反應 MGFY 場次 |
| 可靠輸入 | 點擊、搖動（59Hz）、拖曳；傾斜與陀螺儀**未驗證** | Stage 0 |
| iOS | 權限須由 click 觸發（非 pointerdown）；無震動 API | iPhone 實測 |

**三條全平台鐵律**：
1. **判定用 client 時間戳**（`performance.now()+offset`，已對時到伺服器時間軸）。DO 只做排序、去重、廣播。150ms 的傳輸延遲因此不影響任何公平性判定。
2. **本地先回饋**（0ms），網路結果後到再校正。手機上的每一次操作都要在本機立即有視覺/狀態回應。
3. **每個玩家角色頭上都要有名字**——任何遊戲、任何視角，沒有例外。大螢幕上一堆同款小人，
   只靠配色認不出哪個是自己；分割畫面到 8-12 格時更是完全分不出來。名牌一律用 DOM 疊層
   而不是畫進 canvas（中文在低解析度像素緩衝裡會糊掉，而且要容納五個字），角色移動、跳躍、
   旋轉時名牌都要跟著走。分割畫面另外要在每格左上角放該玩家的即時狀態。
   實作細節見風格聖經 §4。

## 0.5 視覺風格（摘要，完整版見風格聖經）

- 內部解析度：大螢幕 **320×180**、手機直式 **160×284**，`image-rendering: pixelated` 整數倍放大
- 每場景 **10–14 色**受限調色盤；著色用色相偏移（暗部偏冷、亮部偏暖），不用加減亮度
- 假 3D：Mode 7 掃描線地面（`z = f/(y-horizon)`）＋深度縮放精靈＋帶狀多邊形；多人分割用 WebGL 單 context + `gl.viewport`
- 質感：Bayer 4×4 抖動 ＋ smoothstep punch（**構圖用形狀，質感用抖動**）
- 人物 7×9 像素起跳，字串精靈＋換調色盤＝換人；全部遊戲共用同一套精靈
- 複雜靜態背景**畫一次快取**（實測 11ms 一次性、之後 0.3ms/幀）

美術資源量：**零圖檔**。所有畫面程序化生成，這是刻意的架構決定（美術要求最低、風格自動統一、repo 保持無 build step）。

## 1. 木頭人・混合指令 `#1`　→ ✅ 已實作（見 games.md）

**一句話**：一二三木頭人，但「木頭人」時的指令是隨機混合的——搖、點顏色、衝、不要動。

- **回合**：鬼背對 3–6 秒（隨機）出一道指令 → 鬼轉身 1.5–3 秒「不要動」。10 回合，錯最少的贏。
- **指令池**：搖 3 下／點紅色／狂點／衝（連續搖）／**不要動**（轉身時強制）。指令當機率權重表，後期加快。
- **輸入**：點擊＋搖動＋靜止偵測（加速度變異數 < 門檻，門檻做成滑桿，比照 Stage 0）。
- **判定**：轉身時刻 = DO 蓋章廣播的伺服器時間；違規 = client 在轉身後仍有輸入事件（client 時間戳）。**完全延遲免疫。**
- **大螢幕**：Mode 7 草地＋遠處 3× 大的鬼（背對/轉身兩張精靈）＋每人一隻小人，違規紅 ✗ 退格。
- **手機**：全螢幕大字指令鏡像＋巨大按鈕；「不要動」時整片變紅、任何觸碰即犯規。
- **遙測**：每回合 {指令, 轉身時刻, 各玩家反應/違規, uplink}。順便量「靜止偵測誤判率」——長輩手抖數據。
- **估時**：1.5 天（含 stamp.js 抽出）。**風險：低。**

## 2. 下坡滑雪・第一人稱 `#3`　→ ✅ 已實作（見 games.md）

**一句話**：現有滑雪原型換上 Mode 7 第一人稱視覺，加轉彎與跳躍。

- **輸入**：加速=搖動（已驗證）；**轉彎=傾斜 gamma**（開局歸零校準，死區 ±4°，靈敏度滑桿）；**跳躍=點螢幕**（離散輸入，不與搖動訊號打架）。
- **賽道**：程序化：中線 = 疊加正弦；樹/旗/跳台按世界座標播種。賽道寬 ≥ 玩家在 150ms 內的最大橫移 ×3（把「精準微調」設計掉）。
- **判定**:撞樹減速 1.5s（不死）,由 client 判定後上報（信任 client 基準版）；跳台命中用 client 時間戳。
- **大螢幕**：8 分割 WebGL 各玩家第一人稱（/bench 已證明 1ms/幀）；**手機同步顯示自己的第一人稱**（已有初版）。
- **降級**：傾斜手感若不行（§7 A/B 未做），退回直線模式——現有原型已證可玩。
- **遙測**：tilt 上報 15Hz {gamma, speed, dist}；量傾斜控制在 150ms 下的主觀手感（1–5 分）＝**handoff §7 的 client 權威半場**。
- **估時**：2 天（引擎抽出後）。**風險：中（傾斜未驗證）。**

## 3. 砸罐子・彈射保齡 `#4`　→ ✅ 已實作（見 games.md）——改為全員齊砸同一座塔，揮擲＋拉弓

**一句話**：憤怒鳥式拉弓，把 Mode 7 深處的方塊塔砸垮。

- **輸入**：彈弓模式（拖曳後拉、放開發射：角度+力道）；甩投模式（揮動峰值=力道，方向固定）。長輩用彈弓、小孩用甩投。
- **物理**：**決定性**格子化剛體（軸對齊、固定 dt=16.6ms、整數化位置）。手機只上傳發射參數＋回合亂數種子由 DO 發——各端算出完全相同的結果，**延遲只影響動畫開始時間**。
- **塔**：4×5 起，之後加寬加高、加「年獸」獎勵塊。倒塌判定 = 方塊位移 > 0.5 格。
- **大螢幕**：Mode 7 地面＋深度方塊（風格聖經 §2.4），輪流發射全場觀戰——這款要的就是圍觀吶喊。
- **遙測**：發射參數分布（力道/角度）、彈弓 vs 甩投的命中差、物理一致性校驗（各端結果 hash 比對）。
- **估時**：2.5 天（物理 1 天、可完全離線開發）。**風險：中（程式量最大，無網路風險）。**

## 4. 名畫變色龍 `#6`　→ ✅ 已實作（見 games.md）——手機雷射筆指向＋蓋章搶快

**一句話**：pixel art 名畫裡藏著染成背景色的變色龍，20 秒內蓋章抓出來。

完整規格已獨立成文件：[`docs/game6-masterpiece.md`](game6-masterpiece.md)。視覺原型已上線（`/game6`，四張畫：星夜/神奈川/吶喊/睡蓮，重繪 11ms、每幀 0.3ms）。

- **難度=ΔE**：偽裝強度連續可調並換算成小人與背景的 ΔE；長輩 55–70、一般 35–50、高手 22–32，<20 禁用（MGFY 實測的同一把尺）。公平破綻=隨機眨眼。
- **輸入主方案**：陀螺儀瞄準＋點擊——**全案最大未驗證風險**，開發前先做一小時瞄準探針（漂移/手抖半徑/到達時間），手抖半徑直接決定小人尺寸。**降級方案（手機縮圖直接點）必須並行實作**，用已驗證的觸控座標，先讓遊戲成立。
- **判定**：蓋章 client 時間戳、DO 排序去重（與 #1 共用 stamp.js）；蓋中 +3、蓋錯 −1。
- **估時**：降級版 1 天（畫已畫好）；陀螺儀版視探針結果。**風險：主方案高、降級版低。**

## 5. 翻牌記憶・搶配對 `#9`　→ 第二批

**一句話**：神經衰弱，開局亮牌 10 秒，然後全場搶翻。

- **牌面**：pixel 圖示（食物/動物/花色，程序化精靈），**明度對比 ≥25%**——不吃 ΔE 的虧。
- **張數**：8→16→32→64；64 是手機觸控上限（8×8 每格 ~52pt）。手機顯示同布局縮圖直接點。
- **判定**：翻牌意圖 client 時間戳，DO 對「同一張牌」排先後（stamp.js）；翻對保留＋計分，翻錯 1.2 秒後全場可見地蓋回。
- **大螢幕**：假 3D 牌桌（列深度縮放），翻牌動畫 `width=|cos(π·flip)|`（**注意第一版的公式反了**，已修，見 git log）。
- **遙測**：搶同一張牌的時間戳差分布——**探針 A 的正式數據**：RTT 差 30ms 的兩人，慢者勝率多少。
- **估時**：1 天。**風險：最低。**

## 6. 接力快炒・辦桌大戰 `#11`　→ 第四批

**一句話**：Overcooked 拿掉自由移動——每人固定工位，接力出菜，兩隊對抗。

- **關鍵決定**：**不做自由移動**（最貴、最吃延遲的部分整個刪掉）。每工序=本地小遊戲做完上報，延遲免疫。
- **工序↔輸入**：翻鍋=搖動、起鍋=時機點擊（判定窗 client 時間戳）、揉麵/拋餅=拖曳、灑料=傾斜、上菜=點擊。一款遊戲把全部輸入烤熟。
- **菜單**：5 系列 × 4–5 道（中式熱炒/中式炸物/西式炸物/義式 Pizza/日式串燒），每道 3–4 工序、越後面判定窗越窄。**先做熱炒＋Pizza 兩系列驗手感再量產。**
- **大螢幕**：兩條產線俯視（已有 mockup 排版），工位火光/油泡/拋餅動畫；出菜瞬間全場特寫。
- **遙測**：每工序完成時間與失誤、接力交棒延遲（上一位完成→下一位開始）。
- **估時**：3 天（內容量大）。**風險：中（工程低、內容多）。**
